# Шаблоны композиции экранного UI

Каталог содержит универсальные, нейтральные к фреймворку шаблоны композиции
содержимого и запускаемые эталонные примеры. Он не содержит боевой интерфейс,
экраны проекта или точные оболочки устройств.

Каждый шаблон содержит `ID`, версию, совместимые паттерны, обязательные входные
данные, слоты компонентов, состояния, действия, переходы и правила адаптивности
содержимого. Контракт viewport задаёт ограничения композиции, а не внешнюю
геометрию устройства. Эталонный прототип служит примером композиции
(`reference-only`), а не готовым проектным экраном.

Каноническая среда выполнения — HTML/CSS/JS, нейтральная к фреймворку.
Прототипы запускаются локально с тестовыми данными-заглушками (fixture data) и
не требуют API проекта.

Для каждого из 14 зарегистрированных шаблонов в `manifest.json` указан отдельный
`template_path` с запускаемым `index.html`; общие CSS/JS и контракт находятся в
`эталонный-шаблон/`.

Для списков доступны отдельные экранные эталоны табличного представления и карточной ленты. Выбор между ними выполняется по структуре данных и задаче пользователя, а не по одному визуальному предпочтению.

`лендинг/index.html` — составной эталон многораздельной страницы. В нём есть
вариант с формой и без формы; форма и другие необязательные блоки попадают в
проект только при подтверждённых входах. Ссылки на базовые паттерны хранятся
по блокам в `manifest.json`, а у всего эталона `pattern_id: null`.
Точная проверка ширины 375 CSS px и переполнения выполняется через
`tests/test_landing_viewport.py`: обычный headless Chrome может увеличить
внутреннюю ширину окна при параметре `--window-size` меньше своего минимума.

## Публичный каталог

- `manifest.json` — машиночитаемый каталог шаблонов;
- `контракт-пула-экранов.yml` — контракт machine-readable screen pool проекта-потребителя;
- `эталонный-шаблон/` — общий каркас HTML/CSS/JS для адаптации;
- `контракт-шаблона.md` — контракт входных данных, результата и проверки.
- `эталонный-шаблон/визуальный-базис.json` — состав runtime и visual проверок.
- `../screen-shell-integration-contract.md` — привязка композиции к внешнему каталогу оболочек.

- Рекомендуемый порядок — сначала зафиксировать пул экранов и матрицу viewport.
  По прямому запросу разработчика агент может начать раньше; такой пакет остаётся
  черновым до подтверждения пула.
- Пул экранов принадлежит проекту-потребителю: каталог публикует его контракт и
  validator, но не добавляет продуктовые экраны и размеры устройств.
- Для каждого выбранного визуального экрана, viewport и ориентации проект-потребитель
  связывает шаблон содержимого с точной внешней оболочкой. Если оболочки нет,
  фиксируется `GAP`; эталонный прототип каталога не подставляется вместо неё.
- Идентификатор `mobile-touch-shell-screen` сохранён для совместимости. Слово
  `shell` в нём обозначает тип композиции и не означает наличие оболочки устройства.
