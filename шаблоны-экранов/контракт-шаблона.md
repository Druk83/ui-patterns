# Контракт шаблона экранного UI (screen UI template contract)

## Контракт входных данных (input contract)

- `screen_id`, заголовок, назначение и задача пользователя;
- `screen_type`, маршрут или точка входа и роли пользователей;
- идентификаторы выбранных паттерна и шаблона;
- подтверждённая матрица областей отображения (viewport matrix) в CSS px;
- соответствие системы дизайна проекта (design system), если оно задано;
- описание тестовых данных-заглушек (fixture data).

## Контракт результата (output contract)

- запускаемый preview со статусом `reference-only`;
- слоты компонентов и зоны layout;
- действия, состояния, переходы и пути обработки ошибок/восстановления;
- адаптивные варианты и варианты ориентации;
- хуки доступности, переполнения и порядка фокуса;
- reference manifest и артефакты визуальной проверки.

## Порядок выбора

1. Проект формирует и подтверждает screen pool по `контракт-пула-экранов.yml`.
2. Для каждого подтверждённого экрана фиксируется viewport-кандидат в CSS px,
   источник, обоснование, responsive-условия и статус.
3. После подтверждения пула выбирается `template_id` и его revision.
4. `reference-prototype-check.py` запускает preview, проверяет состояния и создаёт
   временные screenshots для подтверждённых viewport. Для полного набора шаблонов
   runtime viewport передаётся явно через `--all-templates --viewport WIDTHxHEIGHT`.

Отсутствующие решения проекта фиксируются как `GAP`; универсальные значения не
могут их заменять.
