# Контракт шаблона композиции экранного UI

## Контракт входных данных (input contract)

- `screen_id`, заголовок, назначение и задача пользователя;
- `screen_type`, маршрут или точка входа и роли пользователей;
- идентификаторы выбранных паттерна и шаблона;
- матрица областей отображения (viewport matrix) с источниками, обоснованием,
  ориентацией и размерами в CSS px; она может быть черновой при раннем начале;
- соответствие системы дизайна проекта (design system), если оно задано;
- описание тестовых данных-заглушек (fixture data).

## Контракт результата (output contract)

- запускаемый эталонный preview со статусом `reference-only`;
- слоты компонентов и зоны содержимого; внешний shell в шаблон не входит;
- действия, состояния, переходы и пути обработки ошибок/восстановления;
- responsive-поведение содержимого и точки его перестроения; точная геометрия
  выбранной ориентации берётся из каталога оболочек проекта-потребителя;
- хуки доступности, переполнения и порядка фокуса;
- reference manifest со статусом привязки к оболочке и артефакты визуальной проверки.

## Порядок выбора

1. Рекомендуется сначала сформировать пул экранов и предложить разработчику
   viewport-кандидаты. По прямому запросу UI можно прорабатывать до подтверждения
   пула; такие результаты маркируются `draft` или `proposed`.
2. Для каждого выбранного визуального экрана и viewport указываются CSS px,
   ориентация, источник, обоснование, responsive-условия и статус.
3. Выбирается `template_id` и его revision как шаблон композиции содержимого.
4. Для каждого сочетания «экран × viewport × ориентация» в каталоге потребителя
   находится точная оболочка; в UI-спецификации фиксируются её URL, неизменяемая
   ревизия, `shell_id` и `viewport_id`. Правила находятся в
   `../screen-shell-integration-contract.md`.
5. При отсутствии точной оболочки создаётся `GAP`. Агент может показать черновую
   композицию содержимого, но не выдаёт её за макет точного устройства. Статус
   `not_applicable` подходит только для невизуального артефакта; голосовой или
   естественный интерфейс с визуальным экраном также требует оболочку.
6. `reference-prototype-check.py` запускает preview, проверяет состояния и создаёт
   временные screenshots. Для полного набора шаблонов runtime viewport передаётся
   явно через `--all-templates --viewport WIDTHxHEIGHT`; эти тестовые размеры не
   являются библиотекой устройств или рекомендацией потребителю.

Отсутствующие решения проекта фиксируются как `GAP`; универсальные значения не
могут их заменять.

## Безопасность

Шаблоны не должны содержать вызовы боевого API, секреты, продуктовые или
персональные данные. Эталонные примеры используют только тестовые данные-заглушки
и не изображают точный экран или устройство потребителя без подтверждённой
оболочки.
